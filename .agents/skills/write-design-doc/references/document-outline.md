# 文档结构参考

新建设计文档或需要重组内容时使用此参考。章节按问题规模选择、合并或省略；小型计划可以只用几个段落。默认中文，用户另有要求时遵从用户。

## 设计文档

| 内容 | 应回答的问题 |
| --- | --- |
| 标题与状态 | 设计的对象是什么？是草案、已确认还是已被替代？只记录有依据的作者、日期、确认信息 |
| 问题与背景 | 当前哪里有问题？为什么需要改变？不看聊天记录的读者能否理解？ |
| 目标与范围 | 完成后有什么可观察的改善？哪些相邻诉求在本次范围外？ |
| 场景与方案 | 给定具体输入，使用者或组件如何完成任务？组件及数据怎样连接？ |
| 关键决策 | 什么约束影响选择？有哪些强替代方案？为何采用当前方案，承担什么代价？ |
| 接口与数据 | API、CLI 或文件格式是什么？操作何时算完成？调用方能观察哪些状态？ |
| 验证与交付 | 如何判断目标达到？分阶段交付什么，前置依赖是什么？ |
| 未决问题 | 问题、影响、候选方案及下一步是什么？是否阻止某个实施阶段？ |

涉及运行服务、外部依赖或敏感数据时，按需要补充性能与规模目标、观测与日志、运行环境、信任边界、数据保留及许可证。术语优先就地解释，较多时设术语表。相关资料就近链接。

新建完整设计时给关键取舍和未决问题一个明确位置；没有未决问题可以说明。解决问题后留下决定及理由，保留原讨论或稳定链接，便于追溯。普通局部修订无需为无关内容新增章节。

## 实施计划

基于已确认设计编写时，引用设计作为决策依据。计划说明实施顺序、阶段依赖、每阶段的产物和验证，以及适用的迁移、恢复或发布步骤。没有估算依据时给阶段顺序，不编造日历日期。

可采用以下写法，按实际工作展开：

```text
目标与设计依据
阶段一：产物、前置条件、验证方式
阶段二：产物、前置条件、验证方式
风险与待决事项：影响、解决方法、下一步
完成条件
```

## 未决事项示例

> 问题：尚未固定评测模型版本。
> 影响：可以先实现离线流程，但正式基线成绩无法视为固定配置的结果。
> 选项：固定可用模型快照，或记录浮动模型标识并限制可复现性声明。
> 下一步：检查服务提供的版本标识，在正式运行前固定配置。

该示例仅展示如何记录问题，不为当前项目新增决策。
